# PayPal incoming payments

Status: approved 2026-10-01. Deviations go to `2026-10-01-paypal-deviations.md`.

## Goal

Read PayPal "you received money" emails like CAKE/Timo notifications: store the transaction, send a Web Push, and fire the order webhook when the PayPal note carries the order code. Everything else PayPal sends is ignored.

## Findings (from `mail-template/paypal/*.eml`, gitignored)

- Sender `service@intl.paypal.com`; DKIM `d=intl.paypal.com` signs `From`, `To`, `Date`. All 6 samples pass `verifyBankDkim` against live DNS.
- The body is Vietnamese even when the subject is English. Three kinds:
  - received: `<payer> đã gửi cho bạn 1,00 $ USD.`, `Mã giao dịch`, optional `Ghi chú từ <payer>:` + note
  - paid: `Bạn đã trả 2,12 $ USD cho <merchant>`
  - authorized (pending): `Bạn đã ủy quyền thanh toán 2,57 $ USD cho <merchant>`
- The body has a date without a time, in three formats. The signed `Date` header has the exact time.
- Amounts are not VND and have decimals (`1,00 $ USD`).

## Design

1. **Registry** (`src/core/banks.ts`): add `{ code: 'PAYPAL', senders: ['service@intl.paypal.com'], dkimDomain: 'intl.paypal.com' }`. Gmail OAuth, IMAP and ingest already read `BANKS`, so the sender filter, `To` check and DKIM apply unchanged.
2. **Parser contract**: `parse(lines, sentAt)` returns `ParsedTxn`, `null` for a sender email that is not a transaction, or throws `ParseError` for a broken template. Ingest maps `null` to `{ status: 'ignored' }` so PayPal's paid/authorized/marketing mail never sets `parse_failed`. CAKE/Timo ignore `sentAt` and never return `null`.
3. **`parsePaypal`**: matches `^(.+) đã gửi cho bạn ([\d.,]+) \S+ ([A-Z]{3})\.$`.
   - `amount`: digits only, i.e. minor units (`1,00 $ USD` → `100`). PayPal prints the currency's own decimals, so this is right for 0-decimal currencies too.
   - `currency`: the 3-letter code. `bankTxnId`: value after `Mã giao dịch`. `counterparty.name`: the payer.
   - `description`: the line after `Ghi chú từ <payer>:`, else `''`. Order codes are extracted from it as for banks.
   - `occurredAt`: `sentAt` (the signed `Date` header). A missing `Date` means `ParseError`.
4. **Money**: `ParsedTxn.currency?: string` (absent = `VND`). Migration: enum `bank` gets `PAYPAL`; `transactions.currency text not null default 'VND'`. `amount` stays an integer in minor units; VND has no minor unit, so existing rows keep their meaning. The webhook sends the stored currency instead of the hardcoded `'VND'`.
5. **Readers**: REST transactions, share, deliveries and MCP return `currency`. MCP `get_payment_status` takes `currency` (default `VND`) and only sums matching payments. Push title and web pages use `formatMoney(amount, currency)` (`Intl.NumberFormat` with the currency's fraction digits).
6. **UI/API enums**: `BANK_NAMES.PAYPAL = 'PayPal'`; the zod bank enums accept `PAYPAL`. Existing configs keep their banks; users tick PayPal themselves. VietQR is unaffected (`vietnam-qr-pay` has no `paypal` key).

Out of scope: English bodies and other PayPal sender addresses (no samples), storing paid/authorized mail, currency-aware amount filters (min/max compare raw minor units; documented).
